# Amazon S3

S3 (Simple Storage Service) is the default data lake storage on AWS — the equivalent of ADLS Gen2 on Azure.

---

## What Is S3?

S3 is object storage. Every file is an "object" stored in a "bucket." Unlike ADLS, S3 has a flat namespace — folders are simulated with `/` prefixes. For analytics, this doesn't matter.

```
s3://my-data-lake/
├── bronze/
│   └── orders/year=2024/month=01/
│       └── part-00000.parquet
├── silver/
│   └── orders/
└── gold/
    └── fact_sales/
```

**S3 URI format:** `s3://bucket-name/prefix/path/`

---

## Key Concepts

| Concept | Description |
|---------|-------------|
| **Bucket** | Top-level container — globally unique name |
| **Object** | File + metadata stored in a bucket |
| **Prefix** | "Folder" path — just part of the object key |
| **Storage Class** | Cost tier — Standard, Infrequent Access, Glacier |
| **Versioning** | Keep all versions of an object |
| **Lifecycle Rule** | Auto-move/delete objects based on age |

## Reading S3 from Spark (EMR / Glue)

```python
# Read Parquet from S3
df = spark.read.parquet("s3://my-data-lake/silver/orders/")

# Read Delta table (requires delta-core JAR)
df = spark.read.format("delta").load("s3://my-data-lake/silver/orders_delta/")

# Write partitioned Parquet to S3
df.write \
    .partitionBy("year", "month") \
    .mode("overwrite") \
    .parquet("s3://my-data-lake/bronze/orders/")
```

## IAM Access Control

S3 access is controlled via IAM roles and bucket policies. No storage account keys:

```json
// Bucket policy — allow specific IAM role to read
{
  "Version": "2012-10-17",
  "Statement": [{
    "Effect": "Allow",
    "Principal": {"AWS": "arn:aws:iam::123456789:role/EMRJobRole"},
    "Action": ["s3:GetObject", "s3:ListBucket"],
    "Resource": [
      "arn:aws:s3:::my-data-lake",
      "arn:aws:s3:::my-data-lake/*"
    ]
  }]
}
```

In practice: attach an IAM role to your EMR cluster or Glue job — it inherits S3 access automatically.

## Lifecycle Management

```json
{
  "Rules": [{
    "ID": "archive-bronze",
    "Filter": {"Prefix": "bronze/"},
    "Status": "Enabled",
    "Transitions": [
      {"Days": 30, "StorageClass": "STANDARD_IA"},
      {"Days": 90, "StorageClass": "GLACIER"}
    ],
    "Expiration": {"Days": 365}
  }]
}
```

## S3 vs ADLS Gen2

| Feature | S3 | ADLS Gen2 |
|---------|----|-----------|
| Namespace | Flat (simulated folders) | Hierarchical (real directories) |
| ACLs | Bucket policies + IAM | RBAC + POSIX ACLs |
| Access protocol | s3:// | abfss:// |
| Delta Lake support | Yes (via open source) | Yes (via open source) |
| Native integration | EMR, Glue, Athena | ADF, Databricks, Synapse |

---

## Best Practices

- Enable versioning on Silver and Gold buckets (protects against accidental overwrites)
- Block all public access at the account level
- Use S3 server-side encryption (SSE-S3 or SSE-KMS)
- Use Lifecycle Rules — Bronze data > 90 days should go to Glacier
- Never use root account access keys — always use IAM roles
